# Changelog

## Unreleased — 2026-09-21 (searchable web backends)

- **The web-search provider is now a real choice, not four names for one
  service.** Automatic / Google / Bing were all the self-hosted SearXNG on
  vault-vps, only with a different engine set. The picker in **Settings ›
  Models › Web search** and `⌘K` › **Search providers** now offers Google,
  Bing, DuckDuckGo, and News through that stack, plus **Tavily** and **Brave**
  called directly from the app with a Keychain key.

  **Automatic** is the Pi lane order: Tavily when a Tavily key is stored, then
  the self-hosted SearXNG, then Brave when a Brave key is stored. A backend is
  skipped when its key is missing and fallen through when it throws or returns
  nothing, so a SearchXNG outage no longer loses the answer to a dead free
  stack. Explicit Tavily or Brave without a key says so instead of failing
  quietly.

  The two keys sit in the same owner-only Keychain as provider keys, under
  stable feature names rather than a fabricated provider UUID. They are never
  written to settings, logs, or the repository. Tavily and Brave send the query
  to that provider; SearXNG stays on the private VPS.

## Unreleased — 2026-09-20 (the `/` palette)

- **Typing `/` in the composer now opens the command list.** The placeholder
  has read "Ask anything, @ to attach, or / for commands…" since v1.4, and
  typing `/` opened nothing. The `@` half had a trigger and a menu; `/` had
  neither, and the fuzzy matcher that would have driven it was drawn in one
  place only, the launcher's root search, which never renders on a chat
  surface.

  Nothing about the commands themselves changed. `/new` and `/clear` were
  already routed, and every saved-prompt alias on the `/` prefix has expanded
  through `SavedPromptResolver` on both surfaces for as long as the prefix has
  been `/`. They were simply unnamed anywhere in the app: no menu, no palette
  row, no settings pane, no help text. The only place either was ever printed
  was the error you got for typing a different one.

  The palette has no search field of its own, because the draft is the
  search: the `/` stays where it was typed, the rows narrow as the name is
  typed, and the composer keeps the keyboard. `↑` `↓` move, Return takes the
  highlighted row into the draft rather than sending it, which leaves room for
  an argument and keeps a destructive `/clear` two keystrokes away rather than
  one. Escape closes the list and leaves the draft alone.

- **Skills can be asked for by name.** The skills in `~/.claude/skills` were
  reachable only when the model chose to call `read_skill`. `/<skill>` now
  puts that skill's own text in front of the question, capped as it always was
  at twelve thousand characters. A built-in or a saved prompt of the same name
  still wins, a name that is not a skill folder holding a `SKILL.md` still
  reaches the unknown-command refusal, and the composer says "Runs the
  <name> skill" before Send, so that much guidance is never added silently.
  The thread records which skill ran.

## Unreleased — 2026-09-20 (later)

- **Quick Launch can now lay out its own AI Chat window.** Every window
  layout and move works on it: halves, thirds, two thirds, quarters, sixths,
  the sixths, Center, Restore, the display moves, and the Left Half cycle
  that steps half to two thirds to a third. macOS's own Move & Resize menu
  has halves and quarters but no thirds at all, and no keys on any of them,
  so this is the only way to put the chat window on the first third by
  hotkey.

  Three things were in the way, all of them assumptions that the layouts only
  ever act on the app *behind* the launcher. The target resolver skips this
  process by design. The chat window's view model was built with no window
  manager at all, so the command died at a guard before the process check
  even mattered. And the apply path hides the window first, for screen
  capture, which would have ordered the chat window out and then resized it.

  A layout picked in the launcher acts on the chat window when that window is
  the one in front; the chat's own palette always acts on it. Otherwise
  nothing changes: the app behind the launcher is still the target. The
  actuator is `NSWindow.setFrame`, not Accessibility, which is the supported
  call for an app's own window, and the geometry is the same `WindowLayout`
  and `WindowCycling` the external path uses, so the two cannot behave
  differently. The top-left coordinate conversion both paths need is now
  written once.

## Unreleased — 2026-09-20

The AI Chat window, after a deep read of where its latency and its clutter
actually came from (`docs/ai-chat-deep-dive-20260920.md`).

- **The AI Chat window had no menu bar, and now it can be tiled.** Two faults,
  one on top of the other. The menu was installed only `if NSApp.mainMenu ==
  nil`, which was never true, because the SwiftUI `App` lifecycle installs a
  bar holding the app menu alone at launch. So the chat window came up with
  no Edit menu, no View menu and no Window menu at all. And because there was
  no Window menu, `NSApp.windowsMenu` was never set either, so macOS never
  added its own window commands. Our bar replaces the SwiftUI one now, and
  the Window menu is handed to AppKit once the bar is installed, which brings
  Fill, Center, Move & Resize (halves, quarters, arrange, return to previous
  size), Full Screen Tile, Move to Display and the window list. The window
  itself was always an ordinary titled, resizable window; it simply never
  told the system it had a Window menu to put them in.
- **A long chat no longer slows down while an answer streams.** All three
  markdown caches failed at once. The segment cache held a single entry, so a
  thread of several answers missed on every one of them and re-parsed each
  answer on every body pass. The render and height caches held 24 entries
  each and were keyed by the text, and a streaming answer produces new text
  about thirty times a second, so within a second they held nothing but
  snapshots of the answer in flight and every finished answer above had been
  evicted. Each miss cost a full CommonMark parse and a text layout. Answer
  text is now cached in a bounded store that keeps the answer still arriving
  in its own slot, where it cannot displace the answers above it.
- **Streaming no longer waits for the disk.** The durable checkpoint rewrites
  the whole conversation file and fsyncs it twice, and it was awaited inside
  the loop consuming the model's tokens, every 800 characters. It is started
  and not awaited now, one at a time; a checkpoint skipped while another is
  in flight costs nothing, because the next carries what it would have
  written and the archive serialises its own writes.
- **The composer scope pill is gone, and the tools are always offered.** In a
  chat with no attachment every tool was already allowed, so the only thing a
  click could do was withhold them, and because the label was chosen before
  the override was read it went on saying "Standard chat" while it did. The
  withhold itself is gone too: a grounded request was never told the tools
  existed, so the model could not judge whether it needed one. It is offered
  every enabled tool now and told, in the system prompt, that a source is
  attached and to answer from it. Attachment scoping is unchanged, so
  "summarise this file" still reads the file.
- **The composer names the destination only when it is worth naming.** "Will
  send to DeepSeek API" was on screen before every message and said nothing
  the user had not chosen. The line is drawn now only for a blocked route, an
  on-Mac route, or an image going somewhere other than the chosen model. The
  route is still recorded against every answer, and a missing API key still
  blocks before Send rather than after it.

This amends the approved plan of 17 September on two points: the visible
Attached sources / Broader search control, and the withholding of tools from
a source-grounded request. `docs/chat-harmonization-plan-20260917.md` and
`CLAUDE.md` carry the amendment.

## Unreleased — 2026-09-19

A bug hunt across the app, prompted by a review pass. Everything below is a defect that shipped, not a preference.

- **The Emoji & Symbols grid no longer crashes on the up arrow.** A filtered grid whose match count did not divide by the nine columns produced a negative selection index, and the selection announcement then read past the front of the list. The wrap is a true modulo now, and the up direction is covered by a test; the grid test previously pressed the down direction only.
- **A chat can no longer lose its earlier turns.** The decision to start a new chat was evaluated twice, once to reserve the conversation and again after a web search or page read, and the second evaluation could flip on the five-minute interval and then hand the new chat the old chat's identity. The decision is taken once and frozen. The archive merge is a union as well, so a live conversation thinner than the stored record can no longer replace it.
- **Screen History retention only spends media it can actually delete.** The storage cap counted imported Coast media it can never remove, so the cap stayed out of reach and every pass deleted further owned captures while Coast media stayed. The cap is sized against reclaimable owned bytes, and the cap path never queues a row whose file cannot be removed. The age-based path is unchanged: it still queues an unowned Coast row for metadata removal while leaving its file in place and counting it as retained.
- **A crash while writing a media segment no longer ends capture.** A stage whose manifest was written before its first frame was treated as corrupt forever, so every later capture failed until the directory was removed by hand. An empty stage is recovered now.
- **The retention review was always empty.** `previewPrune` was synchronous where the protocol requires `async throws`, so the protocol's default stub answered instead of the store and the review reported no planned rows whatever the policy said.
- **Credential-shaped JSON is redacted.** The documented `"token": "…"` form escaped redaction, because the pattern required the name to be followed directly by `:` or `=`, so a quoted JSON key such as `{"api_key":"…"}` was written into the stored conversation unchanged. Tool-call arguments and stored errors now redact the quoted and unquoted forms alike.
- **A damaged conversation record is an error, not an empty chat.** Turns, attachments, tool rounds, session links and receipt refs are required on decode, and an extraction document must carry a kind and a name. An absent or null field used to decode as an empty history, which was then persisted over the real one. A damaged record is now reported rather than rewritten.
- **Provider, Keychain and extraction failures say what went wrong.** A non-2xx response reported the status code with the provider's message discarded, a Keychain read error was indistinguishable from a missing key, a 200 with no parseable content completed the turn empty, and an artifact that no longer decoded disappeared from the prompt while the storage view still reported its role as present.
- **Escape during a Vault Search cancels it.** The search published after Escape and dropped the typed question, because the submitted input was never recorded for the enrichment restore path. A cancelled question also no longer reaches the provider.
- **Thousands separators evaluate correctly.** `1,000 + 5` returned 6 and `1,234,567` errored, because any comma between digits was read as a decimal point.
- **The AI Chat window controller is no longer retained by its own view model.** The controller-to-model-to-chat-to-controller cycle is broken, so the window and its model can be released, and the `[weak self]` captures in that initialiser can now actually see nil.
- **The Add Context record names what it could not read.** An unclosed HTML block and the pages OCR skipped are named in the note rather than silently dropped, so a partial read is no longer presented as the whole page. A Type to Click status line also carries an explicit tone now instead of one inferred by matching the controller's English prose, which is why its two error notices tone as an alert rather than as ready.
- **Smaller fixes.** Clear in Clipboard History can no longer be undone by a metadata write already queued on another queue; the attachment extraction cap matches the shared reader instead of being ten times smaller; Unix socket descriptors are close-on-exec so a spawned `python3`, `ssh` or `qlmanage` cannot inherit one; a large stale search batch waits for the in-flight build instead of folding on the main thread; the link reader reads a body in chunks instead of one byte per await; a record write and its file removal are one transaction; recent-chat pin and rename failures are logged rather than discarded; terminal archive writes are consumed, which clears the five compiler warnings that flagged them; and the hot-key registry clears its Carbon hot key when it is released.

## Unreleased — 2026-09-18

- **Snippets and Quicklinks now belong to Quick Launch.** They are stored in an owner-only local catalog instead of depending on Tuna. A surviving Tuna catalog is imported once, missing Tuna files no longer block edits, and unreadable local data is left untouched and shown as an error.
- **Clipboard History and Screenshots keep the footer on a laptop display.** The hung panel is capped to the room under the search field, and the two-pane preview block was a fixed 522 pt, so on a shorter display it pushed the footer and the last rows past the window's bottom edge. The block now shrinks to the room and the list scrolls; the preview space is unchanged where the display has it.
- **Several large screenshots no longer wedge the chat.** Two per-body-pass costs are gone: a picture chip decodes one 48 pt thumbnail per attachment instead of rebuilding an `NSImage` from the full PNG inside the body (and the chip layout asked several times per pass), and the route resolver remembers whether a provider has an API key instead of reading the Keychain on every pass. A heavy chat surface was re-evaluated a few times a second and produced hundreds of `SecItemCopyMatching` reads a second, which held the main thread at 100% CPU. The key cache is cleared when a key or a provider setting changes.

## v1.5.0 — 2026-09-11

Quick AI polish, part one (the small fixes from `docs/ai-chat-plan-20260911.md`, Phase A1).

- **Answers never collapse.** A long answer used to fold to six lines the moment it finished streaming. Now only what you send folds, as in Raycast: a question over ten lines shows its opening lines with Show more, and an answer always shows in full. `⇧⌘M` toggles the newest long question, and only that question's Show more or Collapse shows the key, so an older pill never names a key that folds a different one.
- **Show more and Collapse keep your place.** Both scroll the message's first line to the top of the thread (animated, or a jump with Reduce Motion), so you land on the start of what opened, or next to Show more after it folds.
- **The collapse threshold fits the thread.** A line was counted as 60 characters; the thread's pill column now measures its own line length with a real text layout (about 105 characters at 666 pt of 13 pt text). A 700-character question no longer folds.
- **Recent Chats searches.** While the list is up, the composer filters it by title and by every message in the chat (all words must match, any case). The composer reads "Search chats…" and starts empty; Return opens the highlighted match and clears the text; Escape clears the search first, then returns to the thread.
- **Cleaner chat titles.** A title is made from the question as you typed it, not from the expanded saved prompt or the Add Context preamble the model gets (a chat keeps that text as `titleSource`; older chats fall back to the first message). It drops a leading `/alias` only when the alias is one of your saved prompts (so `/etc/hosts is not updating` keeps its path) and a "search web", "search the web for", "look up", or "find online" command, starts with a capital, is cut at a word under 60 characters, and loses a trailing "?" or ".". A bare `/alias` run on a selection is named for the prompt it ran. A name set with Rename Chat still wins as typed.
- **The composer says what typing does.** "Ask a follow-up…" once a thread exists (unless the next question starts a new chat), "Search chats…" in Recent Chats, "Waiting for the answer… esc stops" while an answer streams, and "Pick an option above… esc stops" while the model's question card waits. A web search or page read now takes the question out of the composer as soon as it starts (it is the pill above), so the field reads the streaming placeholder then too; a search that fails or is stopped puts the question back. Inside the model chooser, Add Context, or the Transform chooser, the composer's Return label is the chooser's own ("Use Model", "Regenerate", "Add", "Run"), so two ↩ hints never disagree.
- **Copy Answer stays open, and Copy Chat is new.** `⇧⌘C` (and Copy Response as the Return action) copies and keeps Quick AI open, with a checkmark and "Copied" in the composer for 1.5 seconds. Copy Chat (`⌥⌘C`, and in `⌘K`) copies the whole thread as a transcript labelled "You:" and the model's name. `⌥⌘C` was checked against every key table in the app and the default global hotkeys.
- **The empty surface names its ways in.** Three quiet lines: `@` adds a window, a selection, or a screen; `⌘P` opens recent chats (it was `⌘J` until AI Chat took that key); `⇧⌘O` changes the model. They go with the first question. `⇧⌘O` now works before the first answer too.
- **The model line is a button.** Click the model name under the title to open the model chooser; picking a model changes it for the next message and sends nothing. Over Recent Chats, Return in the chooser picks the model (it used to open a chat), in the same order Escape closes the layers. While the model's question card waits, the chooser does not open (click, `⇧⌘O`, or `⇧⌘R`), and a chooser already open closes when the card arrives, so ↑↓ and Return always drive what is on screen.
- **Tests no longer touch your clipboard or chat history.** A view model built without a pasteboard now gets an in-memory one, and chat history is only read or written when the app passes the real `chat-history.json` (`historyFileURL`). Before this, `swift test` copied test answers to the system clipboard and could replace the chat history file with test chats.

Quick AI polish, part two (the medium fixes from `docs/ai-chat-plan-20260911.md`, Phase A2).

- **Math is root search's again.** A local answer (math, a unit conversion, a date, a system fact) shows in root search under the input row, the question as a chip over the answer, as v1.3.0 drew it and as Raycast's calculator does. `Tab` and the Ask AI row answer `2+2` there and never open Quick AI. Asked from the Quick AI composer, it stays in the chat: its own answer under its own question pill, with "Local answer" in the header, never a turn of the chat or of its history. Return copies the answer and closes, as the inline answer row does; Escape or the next keystroke clears it. Math that cannot be computed (`1/0`) says so in root search.
- **Command output and Vault Search name their source.** They still use the Quick AI surface, under their own question pill, but the header's second line names the command (or "Vault Search · Current Project") where the model would be. Neither is written to chat history as a model turn, which matches v1.3.0. Clean Link, Caffeinate Status, and Text from Screen results name their command the same way.
- **`↑` recalls, and the thread has scroll keys.** On an empty Quick AI composer `↑` puts the last question back to edit and send again (Raycast), and `↓` does nothing; neither switches chats any more (`⌘[` and `⌘]` still do). PageUp and PageDown, or `⌥↑` and `⌥↓`, scroll the thread by a page, and `⌘↑` and `⌘↓` jump to its top and bottom. The question card, the choosers, and Recent Chats keep `↑↓` for their rows.
- **Stop keeps what arrived, and `⌘R` asks that turn again.** Escape during an answer used to delete the question and the partial answer and put the question back in the composer, so `⌘R` regenerated the turn before it. Now the question stays and the text that arrived is its answer (saved to history like any answer), and `⌘R` asks that same question again, also after a stop before any text. A stop during the web search or page read still puts the question back; a stop or a provider error once the search is done keeps the question like any other (it used to drop it and show the search results with a false "no answer" error). `⌘R` stays in the chat it asks again, with its earlier turns, also past the Start New Chat interval or in an older chat reopened from Recent Chats. It leaves whatever is typed in the composer alone, and an ask that cannot go out (no provider or key, or a provider that is not available) leaves the thread and the composer as they were.
- **The thread follows you only at the bottom.** Streaming text keeps the newest line in view only while you are within about 40 pt of the bottom, and on every new question. Scroll up to read and the text lands below without moving you; a small "↓ Latest" chip floats above the composer, and clicking it or `⌘↓` goes back down and follows again. Show more and the page keys stop following at once, so a stream cannot pull you back mid-read.
- **An error stays with its question.** A provider error keeps the question in the thread and draws the error under it in danger ink with a warning glyph and "Retry ⌘R"; the control or `⌘R` asks it again. A question left without an answer stays on screen but is left out of what the model is sent, so the next question goes out as clean alternating turns. Errors that belong to no question (permissions, no provider, no key) keep the line above the composer.
- **Return while streaming queues a follow-up.** Type while an answer streams and press Return: the text stays in the field, the action reads "Queued ↩", and it is sent when the answer ends. The streaming placeholder now reads "Type a follow-up; it sends when this answer ends". Escape stops the answer and keeps the queued text in the composer, unsent; an error does the same, and clearing the field unqueues it. Return in the question card and the choosers during a stream works again from the composer (it was dropped while the submit that started the stream was still running). A chooser, Add Context, Recent Chats, or the `⌘K` pane or palette still open when the answer ends holds the follow-up: it is sent when that layer closes, and the end of the stream never picks in it. Opening Recent Chats clears the composer, and a queued follow-up with it. A transform waits for the answer too: the Transform chooser does not open during a stream, and a transform started another way stops the answer first, so two answers never stream at once.
- **`⌘K` in Recent Chats acts on the highlighted chat.** It opens that row's own actions (Continue Chat, Copy Last Answer, Rename Chat, Pin or Unpin, Delete Chat) above the composer, and the row keys (`⌘E`, `⇧⌘P`, `⌃X` twice, `⌘↩`) act on the highlighted chat, never on the one that is open; with a search that matches no chat they, and `⌘K`, do nothing. Pinning moves the highlight with the chat; a rename started here comes back here. A pinned chat shows the pin glyph instead of "Pinned · " in its detail, in Recent Chats and the Chats catalog.

Resizable Quick AI (Phase B1 of `docs/ai-chat-plan-20260911.md`).

- **Drag Quick AI larger.** While Quick AI or Recent Chats is up, drag any edge or corner of the window. It never gets smaller than 750 × 475 and never larger than the screen, less a 12 pt margin on each side, and a dragged edge stops at that margin, so the composer never slides under the Dock and the header never under the menu bar. Root search keeps its own measured size and cannot be dragged. After a resize, Escape and Reset Quick AI Size put the search field back where it opened, even after a drag of one side.
- **It remembers the size.** The size is kept when a drag ends, for the next open and after a relaunch (a new `quickAISize` setting; settings from before open at 750 × 475, and no migration runs). Tools inside the chat (Phase C of `docs/ai-chat-plan-20260911.md`).

- **The model can read your memory, your vault, and your skills.** Four read-only tools join `search_web`: `recall_memory` (`recall search <query> --json` over `~/memory`), `recall_today` (`recall today --json`), `search_vault` (the Vault Search SSH lane, in any of its four modes, one try of 8 seconds, then "vault search timed out" to the model, no retry), and `read_skill` (a `SKILL.md` from `~/.claude/skills`, by a name that must match the folder listing; a name with a slash or a dot is refused, and the text is capped at 12,000 characters). Each tool's description says when to call it: memory and the vault only when you ask about your own notes, projects, clients, decisions, or files; a skill when you name one or ask how you do something. `recall` runs with an argv array through `ProcessRunner` with a 5 second timeout. Tool results reach the model marked as data, not instructions.
- **More room, with a clock.** An answer may now call tools over six rounds (was three), and the whole tool loop has 30 seconds (time on a question card does not count). When either runs out, the model gets one last turn with `tool_choice: none` and a note to answer with what it has. A stuck tool is cut at the budget. Before this, an answer that used its last round on a tool call ended with no answer at all. Attachment extraction and cache, package WP-A (`docs/attachments-and-search-spec-20260911.md` sections 2, 3, and 5). Built and tested, not wired in yet: WP-D connects it once the contract text is approved.

- **One reader for every file kind.** `AttachmentExtractor` (an actor) reads a file once, when it is attached, off the main actor. PDF goes through PDFKit page by page; Word, PowerPoint, and Excel through a small in-house ZIP reader on Apple's `Compression` and `XMLParser`; doc, rtf, rtfd, and odt through `NSAttributedString` with the explicit type; HTML through the app's own `HTMLTextExtractor`; text, Markdown, and code by their bytes. No new package, no child process, no WebKit.
- **What each kind gives.** PDF pages carry `--- Page N ---`. Slides follow the deck's own order (not the file names), with speaker notes under `Notes:` and no slide numbers or footers. Sheets carry `--- Sheet "Name" ---` and tab-separated rows, cells placed by their reference, cached formula values, TRUE and FALSE, and the built-in date formats as dates; other date formats stay numbers, and the model is told so. HTML leads with its title. Word tables become tab-separated rows, and a text box is read once.
- **Text is cleaned the same way everywhere.** NFKC (a PDF's "中⽂" reads "中文"; full-width letters read as ASCII), one kind of line ending, no NUL bytes. Code is kept exactly. Text files decode from a byte-order mark, UTF-8, the encoding macOS recorded, Chinese, Japanese, and Korean encodings, then Windows-1252; a NUL byte in the first 8 KB means "Not a text file".
- **Scans are read on this Mac.** A PDF where at least half the pages have almost no text is a scan: the first 10 of those pages go through the app's Vision OCR, and the chip and the model both hear "OCR · pages 1-10 of 40".
- **The caps hold.** 50 MB documents, 20 MB images, 5 MB text files; 200,000 characters an attachment; 300 pages, 300 slides, 10 sheets of 5,000 rows and 100 columns; 20 seconds a read. A cut keeps the head and is said twice: on the chip ("first 200,000 of 250,000 characters", "pages 1-300 of 305") and to the model.
- **Hostile files stop at a limit, never at a crash.** The ZIP reader checks the entry count before it inflates anything, stops inflating at 16 MB an entry and 64 MB an archive whatever the header says (a 200 MB bomb stops in a few milliseconds), refuses encrypted entries, and looks entries up by name only, so `../` in a name is just a name. Office XML with a document type declaration is refused, so no entity is ever expanded. Before AppKit reads an archive, every entry passes the same caps.
- **One line when a file cannot be read.** "Password-protected; not read", "The file is damaged", "No text found (scanned, OCR empty)", "Larger than 50 MB", "Too large once unpacked; not read", "Not a Word document", "No readable text", "Folders cannot be attached; drop the files.", "Keynote files cannot be read. Export to PowerPoint or PDF.", "Reading took too long", and "macOS blocked access. Drop the file or use File…".
- **The file gate.** `AttachmentFileGate` resolves Finder aliases and symbolic links once, reads only a regular file, refuses folders and packages (a `.rtfd` excepted), checks the size from the file's metadata, and waits up to 20 seconds for an iCloud file to download ("Downloading from iCloud…", then "Not downloaded"). Files are read into memory, never mapped.
- **Images go to the vision model smaller.** An attached picture is scaled to 2,048 px on its long side and re-encoded (PNG, or JPEG over 2 MB), which also drops its location and camera data. Its reference keeps no path and no hash.
- **Links are fetched once.** `LinkAttachmentReader` does one GET over http or https, at most 5 redirects and never to another scheme, no cookies, 15 seconds in all, and stops reading at 5 MB. A page gives its title, its final URL, and its text (100,000 characters at most); a PDF link reads as a PDF; an image link goes to the vision model. A page with almost no text gets the one retry through the reader on vault-vps, inside the same 15 seconds.
- **An owner-only text cache.** `AttachmentTextCache` (an actor) keeps extracted text in `Application Support/Quick Launch/attachment-cache/`: folder `0700`, one `<sha256>-v1.json` file per text at `0600`, out of Time Machine backups. An entry expires 7 days after its last use, the cache holds 100 MB and drops the least recently used first, a deleted chat's entries go unless another chat still uses them, and Clear empties the folder. Images never enter it, and a key from a history file must be a real SHA-256, so it can never name a path.
- **Tests.** `OOXMLArchiveTests`, `AttachmentExtractorTests`, `LinkAttachmentReaderTests` (a `URLProtocol` stub and a fake SSH runner), and `AttachmentTextCacheTests` (an injected clock), 76 in all, with every fixture built in the test: docx, pptx, and xlsx through a test ZIP writer, doc, rtf, and odt through AppKit, text, locked, 305-page, and scanned PDFs, two zip bombs, a GB18030 file, and a noisy image. A timing test prints one extraction per kind next to the spec's measurements and fails if any is ten times slower (a 300-page PDF about 30 ms, OCR of one page about 140 ms).

## v1.0.8 — 2026-04-28

Fix: response text was unreadable in dark mode (issues #20, #23).

`MarkdownRenderer` was emitting attributed-string runs without `.foregroundColor`, so `NSTextView` fell back to a static text colour and rendered the response as black-on-dark. The fix sets `.foregroundColor: NSColor.labelColor` on every run — text, code blocks, headings, inline code, and the inter-paragraph newline runs. `labelColor` is a dynamic system colour that resolves per appearance, so the response now adapts in Light, Dark, and Auto.

- 32 markdown-renderer tests, including a new `testEveryGlyphCarriesLabelColor` that walks every character of a multi-paragraph render and asserts each carries `labelColor` (catches missed paths that single-range tests skip).
- No behaviour changes outside the renderer. Settings → Appearance → System / Light / Dark picker is unchanged.

## v1.0.7 — 2026-04-23

Removed the voice-input feature.

v1.0.5 and v1.0.6 shipped a microphone button backed by the `ohr` CLI. On installed, signed, notarized builds it never actually transcribed live microphone input — not once. Three successive patches (in-process `AVCaptureDevice.requestAccess`, audio-input entitlement, single-line entitlement XML for the AMFI kernel parser) each fixed a visible layer without fixing the end-to-end path. Rather than keep patching a subprocess architecture that fights macOS TCC + Hardened Runtime at every turn, the feature is removed in full.

- Mic button, Voice settings tab, `ohr` subprocess wrapper, microphone permission shim, voice fixture + tests — all deleted.
- `NSMicrophoneUsageDescription` removed from Info.plist.
- `com.apple.security.device.audio-input` removed from entitlements.
- Bundled `ohr` helper removed from the build script; releases no longer carry it.
- Full post-mortem kept at `docs/learnings/voice-input-ohr.md` so the next attempt at voice input doesn't repeat these mistakes. Recommendation: use Apple's in-process `Speech` framework, not a spawned CLI.
