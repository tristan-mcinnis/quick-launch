# Changelog

## v1.5.0 — 2026-09-11

Quick AI polish, part one (the small fixes from `docs/ai-chat-plan-20260911.md`, Phase A1).

- **Answers never collapse.** A long answer used to fold to six lines the moment it finished streaming. Now only what you send folds, as in Raycast: a question over ten lines shows its opening lines with Show more, and an answer always shows in full. `⇧⌘M` toggles the newest long question, and only that question's Show more or Collapse shows the key, so an older pill never names a key that folds a different one.
- **Show more and Collapse keep your place.** Both scroll the message's first line to the top of the thread (animated, or a jump with Reduce Motion), so you land on the start of what opened, or next to Show more after it folds.
- **The collapse threshold fits the thread.** A line was counted as 60 characters; the thread's pill column now measures its own line length with a real text layout (about 105 characters at 666 pt of 13 pt text). A 700-character question no longer folds.
- **Recent Chats searches.** While the list is up, the composer filters it by title and by every message in the chat (all words must match, any case). The composer reads "Search chats…" and starts empty; Return opens the highlighted match and clears the text; Escape clears the search first, then returns to the thread.
- **Cleaner chat titles.** A title is made from the question as you typed it, not from the expanded saved prompt or the Add Context preamble the model gets (a chat keeps that text as `titleSource`; older chats fall back to the first message). It drops a leading `/alias` only when the alias is one of your saved prompts (so `/etc/hosts is not updating` keeps its path) and a "search web", "search the web for", "look up", or "find online" command, starts with a capital, is cut at a word under 60 characters, and loses a trailing "?" or ".". A bare `/alias` run on a selection is named for the prompt it ran. A name set with Rename Chat still wins as typed.
- **The composer says what typing does.** "Ask a follow-up…" once a thread exists (unless the next question starts a new chat), "Search chats…" in Recent Chats, "Waiting for the answer… esc stops" while an answer streams, and "Pick an option above… esc stops" while the model's question card waits. A web search or page read now takes the question out of the composer as soon as it starts (it is the pill above), so the field reads the streaming placeholder then too; a search that fails or is stopped puts the question back. Inside the model chooser, Add Context, or the Transform chooser, the composer's Return label is the chooser's own ("Use Model", "Regenerate", "Add", "Run"), so two ↩ hints never disagree.
- **Copy Answer stays open, and Copy Chat is new.** `⇧⌘C` (and Copy Response as the Return action) copies and keeps Quick AI open, with a checkmark and "Copied" in the composer for 1.5 seconds. Copy Chat (`⌥⌘C`, and in `⌘K`) copies the whole thread as a transcript labelled "You:" and the model's name. `⌥⌘C` was checked against every key table in the app and the default global hotkeys.
- **The empty surface names its ways in.** Three quiet lines: `@` adds a window, a selection, or a screen; `⌘J` opens recent chats; `⇧⌘O` changes the model. They go with the first question. `⇧⌘O` now works before the first answer too.
- **The model line is a button.** Click the model name under the title to open the model chooser; picking a model changes it for the next message and sends nothing. Over Recent Chats, Return in the chooser picks the model (it used to open a chat), in the same order Escape closes the layers. While the model's question card waits, the chooser does not open (click, `⇧⌘O`, or `⇧⌘R`), and a chooser already open closes when the card arrives, so ↑↓ and Return always drive what is on screen.
- **Tests no longer touch your clipboard or chat history.** A view model built without a pasteboard now gets an in-memory one, and chat history is only read or written when the app passes the real `chat-history.json` (`historyFileURL`). Before this, `swift test` copied test answers to the system clipboard and could replace the chat history file with test chats.

Quick AI polish, part two (the medium fixes from `docs/ai-chat-plan-20260911.md`, Phase A2).

- **Math is root search's again.** A local answer (math, a unit conversion, a date, a system fact) shows in root search under the input row, the question as a chip over the answer, as v1.3.0 drew it and as Raycast's calculator does. `Tab` and the Ask AI row answer `2+2` there and never open Quick AI. Asked from the Quick AI composer, it stays in the chat: its own answer under its own question pill, with "Local answer" in the header, never a turn of the chat or of its history. Return copies the answer and closes, as the inline answer row does; Escape or the next keystroke clears it. Math that cannot be computed (`1/0`) says so in root search.
- **Command output and Vault Search name their source.** They still use the Quick AI surface, under their own question pill, but the header's second line names the command (or "Vault Search · Current Project") where the model would be. Neither is written to chat history as a model turn, which matches v1.3.0. Clean Link, Caffeinate Status, and Text from Screen results name their command the same way.
- **`↑` recalls, and the thread has scroll keys.** On an empty Quick AI composer `↑` puts the last question back to edit and send again (Raycast), and `↓` does nothing; neither switches chats any more (`⌘[` and `⌘]` still do). PageUp and PageDown, or `⌥↑` and `⌥↓`, scroll the thread by a page, and `⌘↑` and `⌘↓` jump to its top and bottom. The question card, the choosers, and Recent Chats keep `↑↓` for their rows.
- **Stop keeps what arrived, and `⌘R` asks that turn again.** Escape during an answer used to delete the question and the partial answer and put the question back in the composer, so `⌘R` regenerated the turn before it. Now the question stays and the text that arrived is its answer (saved to history like any answer), and `⌘R` asks that same question again, also after a stop before any text. A stop during the web search or page read still puts the question back; a stop or a provider error once the search is done keeps the question like any other (it used to drop it and show the search results with a false "no answer" error). `⌘R` stays in the chat it asks again, with its earlier turns, also past the Start New Chat interval or in an older chat reopened from Recent Chats. It leaves whatever is typed in the composer alone, and an ask that cannot go out (no provider or key, or a provider that is not available) leaves the thread and the composer as they were.
- **The thread follows you only at the bottom.** Streaming text keeps the newest line in view only while you are within about 40 pt of the bottom, and on every new question. Scroll up to read and the text lands below without moving you; a small "↓ Latest" chip floats above the composer, and clicking it or `⌘↓` goes back down and follows again. Show more and the page keys stop following at once, so a stream cannot pull you back mid-read.
- **An error stays with its question.** A provider error keeps the question in the thread and draws the error under it in danger ink with a warning glyph and "Retry ⌘R"; the control or `⌘R` asks it again. A question left without an answer stays on screen but is left out of what the model is sent, so the next question goes out as clean alternating turns. Errors that belong to no question (permissions, no provider, no key) keep the line above the composer.
- **Return while streaming queues a follow-up.** Type while an answer streams and press Return: the text stays in the field, the action reads "Queued ↩", and it is sent when the answer ends. The streaming placeholder now reads "Type a follow-up; it sends when this answer ends". Escape stops the answer and keeps the queued text in the composer, unsent; an error does the same, and clearing the field unqueues it. Return in the question card and the choosers during a stream works again from the composer (it was dropped while the submit that started the stream was still running). A chooser, Add Context, Recent Chats, or the `⌘K` pane or palette still open when the answer ends holds the follow-up: it is sent when that layer closes, and the end of the stream never picks in it. Opening Recent Chats clears the composer, and a queued follow-up with it. A transform waits for the answer too: the Transform chooser does not open during a stream, and a transform started another way stops the answer first, so two answers never stream at once.
- **`⌘K` in Recent Chats acts on the highlighted chat.** It opens that row's own actions (Continue Chat, Copy Last Answer, Rename Chat, Pin or Unpin, Delete Chat) above the composer, and the row keys (`⌘E`, `⇧⌘P`, `⌃X` twice, `⌘↩`) act on the highlighted chat, never on the one that is open; with a search that matches no chat they, and `⌘K`, do nothing. Pinning moves the highlight with the chat; a rename started here comes back here. A pinned chat shows the pin glyph instead of "Pinned · " in its detail, in Recent Chats and the Chats catalog.

Resizable Quick AI (Phase B1 of `docs/ai-chat-plan-20260911.md`).

- **Drag Quick AI larger.** While Quick AI or Recent Chats is up, drag any edge or corner of the window. It never gets smaller than 750 × 475 and never larger than the screen, less a 12 pt margin on each side, and a dragged edge stops at that margin, so the composer never slides under the Dock and the header never under the menu bar. Root search keeps its own measured size and cannot be dragged. After a resize, Escape and Reset Quick AI Size put the search field back where it opened, even after a drag of one side.
- **It remembers the size.** The size is kept when a drag ends, for the next open and after a relaunch (a new `quickAISize` setting; settings from before open at 750 × 475, and no migration runs). On a smaller display the window fits the screen and the stored size waits for the larger one, and the window stays where you put it while an answer streams. A window taller than the room under the search field moves up just enough to fit, instead of being cut.
- **The thread stays readable.** In a wider window the header and composer span the window, and the thread stays one centred column, as wide as it is at 750: answers still wrap at 690 pt, and your questions end at the column's right edge. At 750 × 475 nothing moved.
- **Reset Quick AI Size** in `⌘K` goes back to 750 × 475. It shows only after the window was resized.

Tools inside the chat (Phase C of `docs/ai-chat-plan-20260911.md`).

- **The model can read your memory, your vault, and your skills.** Four read-only tools join `search_web`: `recall_memory` (`recall search <query> --json` over `~/memory`), `recall_today` (`recall today --json`), `search_vault` (the Vault Search SSH lane, in any of its four modes, one try of 8 seconds, then "vault search timed out" to the model, no retry), and `read_skill` (a `SKILL.md` from `~/.claude/skills`, by a name that must match the folder listing; a name with a slash or a dot is refused, and the text is capped at 12,000 characters). Each tool's description says when to call it: memory and the vault only when you ask about your own notes, projects, clients, decisions, or files; a skill when you name one or ask how you do something. `recall` runs with an argv array through `ProcessRunner` with a 5 second timeout. Tool results reach the model marked as data, not instructions.
- **More room, with a clock.** An answer may now call tools over six rounds (was three), and the whole tool loop has 30 seconds (time on a question card does not count). When either runs out, the model gets one last turn with `tool_choice: none` and a note to answer with what it has. A stuck tool is cut at the budget. Before this, an answer that used its last round on a tool call ended with no answer at all. The 15 second watchdog on a "search web" answer now stops only a silent model: one that is writing, or has a tool line in, keeps going.
- **Every tool call leaves a line.** "Searched memory: 4 hits", "Searched vault · current: 6 results", "Read today: 2 captures, 31 open tasks", "Read skill: costing", "Searched the web: …", in the thread's tool-line style above the answer, while it streams and after. The lines are saved with the answer, so a chat reopened from Recent Chats or history shows them. The explicit "search web …" line is saved the same way; it used to vanish with the next question.
- **Sources under the answer.** When memory or the vault returns hits, a quiet list under the answer names each source (the file or record title, and its day), five at most, the rest in `⌘K` › Open Source. Memory hits are local files. Vault paths are mapped from `/home/ubuntu/vault-private/` (or vault-relative) to `~/vault/`; a row with no path is listed without an open action. **Open Source** (`⌘O`, and in `⌘K`) opens the one source with `/usr/bin/open` through `ProcessRunner`, or lists them when there are several; a click on a source row does the same. Only a document opens (text, Markdown, PDF, image, Office, or email) inside `~/memory` or `~/vault`, with links followed before the check: never a folder, an app, a script, an executable, or a file `open` would run, install, or follow, such as a `.jar`, a `.webloc`, or a configuration profile.
- **Tools per chat.** `⌘K` › **Tools** (`⌥⌘K`, and before the first answer too) lists Memory, Vault, Skills, and Web search with On or Off; Return turns one on or off for this chat. The choice is kept on the chat (`QuickConversation.enabledTools`); a new chat you start (`⌘N`) begins on the defaults: memory, vault, and skills on, web search per "Let the model search the web". A chat the next question starts on its own (the new-chat interval, a saved-prompt follow-up) keeps the open chat's choice. A tool this Mac cannot run says so and is never offered. The Translator keeps web search only.
- **A context budget.** Before every request, a chat plus its tool results is held to a character budget from the model's context window (three characters a token, half the window, 32,000 tokens when the window is unknown). Over it, the results of the answer's older tool rounds go first, then the oldest turns, and the results the model just fetched only when nothing else is left; the system prompt, the chat's first question, and the current question are never dropped. A line says what was left out.
- **Capture to Memory.** `⌘K` › Capture to Memory (`⌥⌘M`) sends the answer on screen to `recall remember`, confirms in the composer, and leaves a "Captured to memory" checkmark line under the answer. It is your action only; the model cannot call it.

Continue in pi (`docs/ai-chat-plan-20260911.md`, Phase E).

- **Continue in pi (`⌥⌘P`, and in `⌘K` on a Quick AI thread).** The thread goes to a fresh pi session with all of pi's tools, skills, and subagents. Quick Launch writes it as Markdown (the title, then each turn under "You:" or the model's name, the web-search line on the answer it belongs to, and the answer's own source links) to `~/Library/Application Support/Quick Launch/pi-handoff/<time>-<title>.md`, owner-only and capped at the 20 newest files. It starts a detached tmux session named `ql-` plus six characters in your home folder, running `pi @<file> "Continue this conversation from Quick Launch. The thread is attached."`, and opens a new Ghostty window attached to it. The thread then ends with "Opened in pi · tmux session ql-…". Every step is a direct argv launch with a 10 second timeout, never a shell.
- **Ghostty the supported way.** Ghostty's own help says its CLI cannot open a terminal on macOS (`+new-window` is GTK only) and names `open -na Ghostty.app --args …`; Quick Launch runs `open -n -b com.mitchellh.ghostty --args -e tmux attach-session -t ql-…`, so each hand-off is its own Ghostty window that quits when you close it. When Ghostty does not open, the session keeps running, `tmux attach -t ql-…` is copied, and the thread says so.
- **pi starts from the Dock too.** pi is a Node script, and an app started by launchd has no Node on its `PATH`. The session's `PATH` is the tmux server's own, plus the folders of pi, node, and tmux and the usual CLI folders; with no tmux server running yet, the app's `PATH` gets those folders added.
- **`⌥⌘P` was checked free** against every answer action, the overlay's own keys, the `⌘K` row actions of every kind, and the default global hotkeys. Without tmux or pi installed, the action says which one is missing.

Assistants (plan Phase D).

- **A saved AI command with Instructions is an assistant.** `SavedPrompt` gains `systemPrompt`, `enabledTools` (the shared `ChatToolKind` set; nil uses the chat defaults, empty means no tools), and `contextRefs` (skill names). With instructions set and no command, `/alias` alone with nothing selected, `⌘K` › Change Assistant (`⌥⌘A`), or the command's hotkey or `⌘K` row with nothing selected starts or switches the Quick AI chat to it and sends nothing. The chat records it (`QuickConversation.assistantID`) and takes its tools as the chat's tool set; a pinned provider and model become the active ones, as Change Model does. `/alias` with text after it, or with text selected (the launch selection chip or an attached selection), keeps the one-shot transform, and so do the hotkey and `⌘K` row with a selection. A transform never runs inside an assistant chat: it starts a plain chat with no system message. A stale chat is replaced before the pick, a picked assistant with nothing asked yet is never dropped by the new-chat interval, and when the interval starts a new chat for the next question, the assistant goes along with its tools, instructions, and skills (read again for the new chat). `⌘N` starts a plain chat; reopening an assistant chat from Recent Chats brings its assistant back.
- **The system message.** Each request in an assistant chat starts with one system message: the instructions, then each context skill in a `<skill name="…">` block, then the app's own instruction. Skills are read through `SkillLibrary` (only listed `~/.claude/skills` folders, 12,000 characters each), off the main actor, once per chat. `QuickViewModel.skillLibrary` is the optional seam Phase C's `read_skill` uses; nil reads no skills. The OpenAI-compatible service folds it into its single system message; a command provider puts it in `{{systemPrompt}}`, or on stdin when its arguments have no such placeholder. Saved chats keep only the turns.
- **The header names the assistant.** The model line reads "Vault researcher · DeepSeek V4.1 Flash"; the name opens Change Assistant, the model still opens Change Model. Change Assistant floats over the composer: No Assistant (a plain chat), then each assistant with its alias and tools; ↑↓, Return "Use Assistant", Escape. In `⌘K`, an assistant's row reads "Assistant" and picks it, or runs its prompt when text is selected.
- **Settings › AI Commands has an Assistant card.** Instructions, then, once the command is an assistant, Tools (Chat defaults or four switches) and Context skills (an Add Skill menu of the skills folder; a missing skill is marked and skipped). A plain transform shows Instructions only; a command action shows it turned off.
- **Two default assistants.** Vault researcher (`/vault`: vault and memory tools, cites a source for every fact) and STE editor (`/ste`: no tools, ASD-STE100 rules). Configuration version 25 adds them to an existing install once, only where the alias is free; a deleted one stays deleted. The plan named a third ("China Snapshot desk"); it is not seeded.

## v1.3.0 — 2026-09-11

- **Raycast Quick AI parity.** The overlay now matches Raycast's Quick AI surface on the behaviour it was missing, without changing what already worked. Every new control is operable with the keyboard alone and carries an accessibility label. The written target and the gap analysis behind it live in `docs/quick-ai-parity-20260911.md`.
- **Code blocks render as blocks.** A fenced block in an answer shows a header strip with the detected language on the left and Copy and a line-wrap toggle on the right. Long lines scroll sideways by default, exactly as Raycast does, and wrap only when toggled. Copy takes the code alone, with no fence markers, and confirms inline. The overlay and the conversation view share one renderer, so both draw the same block, and each message's controls carry unique identifiers so they cannot collide.
- **Collapsed messages.** A message over ten lines, or a comparably long single paragraph, now renders with its opening lines plus a **Show more** control, and a **Collapse** control once expanded, replacing the silent three-line clip. Shorter messages always show in full. `⌘⇧M` toggles the newest long message.
- **Add Context.** A control to the left of the composer, and typing `@`, open the same menu: Focused Window, Selected Text, Selected Area, and Entire Screen, reusing the existing capture paths. Attached context stays scoped to the message it is sent with, and opening the menu never disturbs a half-typed question.
- **Ask User Question.** When a request is ambiguous, the model can pause and ask a short multiple-choice question inline instead of guessing, and continues with the option you pick. The card lists two to five options with an optional line of detail each; `↑` and `↓` choose and Return answers, and the card stays in the thread afterwards as a record of what was asked and what you chose. It is always on, with no setting to disable it. A malformed question from the model falls back to answering normally rather than stalling the thread.
- **Return on a finished answer follows the Quick AI primary action**, and the footer hint now names what Return will actually do rather than always reading Paste back.
- **`⌘J` opens the thread.** The current conversation opens full height with the recent chat list beside it. History, model, and attachments carry over, and Escape returns to the overlay. It stays inside the overlay window; Quick Launch is still not a chat workspace.
- **Regenerate on another model, change model mid-thread.** `⇧⌘R` opens a keyboard model chooser and reruns the last answer on the model you pick, and **Change Model** is now a `⌘K` action with its own shortcut, switching the active model without regenerating. `⌘R` still regenerates on the same model. **Replace Selection** moved from `⇧⌘R` to `⇧⌘V` to make room, and pastes normally when no answer is on screen.
- **Manage models** (Settings › Models › Manage models) lists every configured model with its provider, Speed, Intelligence, and Context window, a switch to enable or disable it, a **Group by Provider** toggle, and a sort menu offering Brand, Alphabetically, Speed, Intelligence, and Context Window. Disabled models disappear from every model picker in the app. Metadata is curated for the ids this build ships and shown as Unknown for anything else rather than guessed.
- **Reasoning effort per model.** Where a model supports it, its row and the AI Commands editor offer an effort choice with the model default marked as such. The choice carries over between models that support it and resets when you switch to one that does not. It now reaches the wire: DeepSeek receives its thinking block alongside the effort, OpenAI-shaped endpoints and the local daemon receive the plain field, and a request with no effort set is byte-for-byte what it was before.
- **Quick AI settings** (Settings › General › Quick AI) collect the surface's own behaviour: which model the overlay defaults to, whether Return on a finished answer pastes into the previous app or copies, whether the Tab hint appears in search, and how long an idle thread may sit before a new question starts a fresh chat. The Start New Chat choices are 5, 10, 15, or 30 minutes, 1 hour, always, or never, and the old numeric timeout migrates onto the nearest choice.
- **Fallback Commands** (Settings › General) decide what unmatched search text runs on Return. Commands are added from the app's own catalogs, reordered by drag or with the keyboard, and removed with the minus button; Ask AI is the default. The search row's copy now names the command Return will actually run, and Tab still opens Quick AI no matter what heads the list.
- **Model pickers cannot offer a disabled model** any more, in the overlay's model menu or after a refresh.
- The conversation view renders markdown, including code blocks with their copy and wrap controls, instead of falling back to plain text.

- **Learning & Review** (Settings › General) brings the two halves of how Quick Launch learns from you into one card: the existing "Learn from my choices" ranking toggle and its Forget button, beside a new local interaction journal. The journal records *outcomes* at the points they already happen — a chosen launcher row, a query typed and dropped, a retry of that same query inside ten minutes, an action or AI failure, an AI cancellation, a completed or stopped command action, and a global hotkey run — as a bounded, owner-only `interaction-journal.json`: 2 000 events and 30 days by default, both adjustable, `0600`, atomic writes. A row stores a sanitized item identifier, a short category code, and a *keyed* digest of the folded query: HMAC-SHA256 under a random 32-byte key generated on first use and stored owner-only as `interaction-journal-key` (re-checked to `0600` on every load). Repeats still correlate on this Mac, and the digest cannot be recomputed or brute-forced without that file. The query text, and every clipboard, snippet, chat, selection, file, and AI answer value, are never written; only a coarse size band (`1-3`, `8-15`, `32+`) is kept, never an exact character count, and *every* typed text is digested — including a question submitted through the Ask AI row, whose id is the fixed `askAI:ask`. A typed web address is digested too: the launcher's own row identity for it is a stable keyless FNV-1a content hash, which is irreversible in practice but not cryptographic, so the journal re-keys that id under its own HMAC key. The digest is one-way but not a secret store: a short query remains guessable by brute force from the digest plus the key file. A journal file from the first build of this feature migrates in place: rows keep their kind, scope, identifier, detail, time, and marker, the exact length becomes a band, unknown event kinds survive as an unknown row, and the retired keyless digest plus any verbatim identifier are dropped from disk on load. A duplicate of the newest row inside two seconds (the screenshot path learns twice for one Return) collapses to one event, and an abandoned query repeated inside ten minutes is filed as a retry rather than a second abandonment. A submitted request that then fails or is cancelled is never also filed as an abandoned search. Escape now genuinely terminates a running command action through `ProcessRunner`'s cancellation path, so late output cannot reappear, and only a cancellation that really happened is recorded. The card shows event count, file size, the last event time, and how many rows are marked; the last six rows each carry a **Mark wrong** / **Unmark** button — an explicit, reversible marker that is never inferred and never fed into ranking — and **Export…** writes JSON Lines or Markdown through a normal save panel, beside **Reveal in Finder** and **Clear journal**. Turning the journal off stops new recording and says so; events already kept stay, remain exportable and clearable, and still age out. Every clamped retention or cap value renders in its picker, with the current value added when it is not one of the presets. Ranking itself is untouched: the Quicksilver-style exact/related mnemonic plus decayed frecency in `LauncherUsageStore` still works exactly as before, and no journal signal — abandoned searches, failures, or the wrong-choice marker — reaches the ranker. The README's "No telemetry" line is replaced with the accurate claim: no analytics, no telemetry, one bounded local review log that never leaves the Mac.
- Type to Click (`⌃⌥C` by default) now puts gold badges with actual control names over every visible clickable target, without arbitrary generated hint codes. Typing a visible control name, Accessibility role (`button`, `btn`, `field`), or active-app menu path (`File Save As`, `View Sidebar`) fuzzy-filters that map and visibly selects the best result. Return pulses the selected badge and acts. The new **After Return** setting chooses between **Stay open and rescan** for chained steps (the default) and **Dismiss after one action**. Arrow keys, Tab/Shift-Tab, and Control-N/P change selection; on visible controls, Control-Return right-clicks while Command/Shift/Option-Return preserve click modifiers. Menu commands always use their native activation, and frameless closed-menu matches show their selection in the status pill. ## v1.0.8 — 2026-04-28

Fix: response text was unreadable in dark mode (issues #20, #23).

`MarkdownRenderer` was emitting attributed-string runs without `.foregroundColor`, so `NSTextView` fell back to a static text colour and rendered the response as black-on-dark. The fix sets `.foregroundColor: NSColor.labelColor` on every run — text, code blocks, headings, inline code, and the inter-paragraph newline runs. `labelColor` is a dynamic system colour that resolves per appearance, so the response now adapts in Light, Dark, and Auto.

- 32 markdown-renderer tests, including a new `testEveryGlyphCarriesLabelColor` that walks every character of a multi-paragraph render and asserts each carries `labelColor` (catches missed paths that single-range tests skip).
- No behaviour changes outside the renderer. Settings → Appearance → System / Light / Dark picker is unchanged.

## v1.0.7 — 2026-04-23

Removed the voice-input feature.

v1.0.5 and v1.0.6 shipped a microphone button backed by the `ohr` CLI. On installed, signed, notarized builds it never actually transcribed live microphone input — not once. Three successive patches (in-process `AVCaptureDevice.requestAccess`, audio-input entitlement, single-line entitlement XML for the AMFI kernel parser) each fixed a visible layer without fixing the end-to-end path. Rather than keep patching a subprocess architecture that fights macOS TCC + Hardened Runtime at every turn, the feature is removed in full.

- Mic button, Voice settings tab, `ohr` subprocess wrapper, microphone permission shim, voice fixture + tests — all deleted.
- `NSMicrophoneUsageDescription` removed from Info.plist.
- `com.apple.security.device.audio-input` removed from entitlements.
- Bundled `ohr` helper removed from the build script; releases no longer carry it.
- Full post-mortem kept at `docs/learnings/voice-input-ohr.md` so the next attempt at voice input doesn't repeat these mistakes. Recommendation: use Apple's in-process `Speech` framework, not a spawned CLI.

258 tests green.
