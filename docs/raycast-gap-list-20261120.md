# Quick Launch against Raycast: gap list, 2026-11-20

Source: the Raycast manual and developer docs as downloaded on 2026-11-20, read
against `Sources/` at commit `7f5d527`. Six agents compared one area each; six
more re-checked every claim in the code. Claims were read from code, not run
in the app. This file is a snapshot, not a tracker: when a gap is closed, say
so in `CHANGELOG.md`, not here.

Columns: **V** is value to one keyboard-first user (1 to 5). **E** is effort
(S, M, L). **Fit** is against the project contract in `CLAUDE.md`.

## Closed on 2026-11-20 (commit `cafe419`)

Fallback Commands beyond the first, Empty Trash confirm, house command and
snippet-argument hotkeys, `{cursor}`, the three Quicklink slot spellings,
command action quoting and timeout, Forget Learned Ranking, Export All Chats,
owner-only data folders. Rows below that describe these are kept as found.

## Order of work proposed

1. Export and import of settings and data in one file.
2. Next meeting row with Join, and a My Schedule list.
3. Percent math, more cities, time zone conversion.
4. Script commands folder, and a HUD after the launcher closes.
5. Quicklink placeholders, selected text as the argument, links to files.
6. Alias prefix tier, alias badge, alias then space.
7. Skills with descriptions.
8. Claude and Gemini by API key with tools.
9. Auto-switch input source when the launcher opens.
10. Edit a sent message and re-run, Branch Chat, Switch Windows.

Needs a decision: favourites on the empty root, a URL scheme for commands,
currency conversion, snippet auto-expansion, file search by name, dictation,
an MCP client, Hyper Key, the clipboard 200-item cap.

Out of scope: cloud sync, iOS, teams, enterprise, the extension store, themes,
projects, automations, memory, focus sessions, floating notes.

### Root search: built but half-wired, hidden or undocumented

- Fallback Commands list is half-wired: Settings lets you add and reorder many, but only the first one runs or shows (firstFallbackCommandID, Sources/Models/QuickSettings+Defaults.swift:97; readers at Sources/ViewModels/QuickViewModel+LauncherSearch.swift:602 and QuickViewModel+InteractionJournal.swift:485). docs/features.md line 34 does say 'runs the first Fallback Command', so the doc is honest; the reorderable list is what misleads.
- Dead code: LauncherUsageStore.forget(itemID:) has no caller and no test (Sources/Services/LauncherUsageStore.swift:92; grep over Sources and Tests finds the definition only). Forgetting is global only (Sources/Views/SettingsGeneralTab.swift:386).
- Hotkey conflict messages print the raw item id for launcher items: 'This conflicts with the \(configuration.itemID) launcher hotkey' (Sources/Models/QuickSettings+Hotkeys.swift:138 and :164). Built-in hotkeys and saved prompts are named correctly.
- A conflicting item hotkey stays saved but is skipped at registration (Sources/App/AppDelegate+Hotkeys.swift:218-222). Whether the launcher row still shows its hotkey badge is unverified at runtime.
- 'Hide from Quick Launch' is not in the docs: docs/features.md has 0 matches for 'hide from' (grep -i -c). The action kind is hideFromLauncher (Sources/Models/ItemAction.swift:172).
- docs/features.md has no line for the app actions Force Quit and Hide Windows (Sources/Models/ItemAction.swift:233-239) or for Add App; a grep for those words in the file returns nothing. docs/product-scope.md job list jumps from 15 to 18.
- Settings search has no focus key: searchFieldFocused is only ever set to false (Sources/Views/SettingsView.swift:203, :260) and the file has no Cmd-F. Default focus on open is unverified at runtime.
- Hotkeys are split over four Settings places; the Keyboard Shortcuts 'Global Hotkeys' card lists five fixed ones and points elsewhere for the rest (Sources/Views/KeyboardShortcutsSettingsView.swift:87-108).
- Empty root shows only 2 learned items, then Ask AI and the catalog roots (emptyQueryFavouriteRows = 2, Sources/ViewModels/QuickViewModel+QuickAISize.swift:131). 'Pin to top' (docs/features.md line 325) does not reach the empty root; it only boosts typed search and orders the item's own catalog (:186-187, :483).
- Type to Click, the stand-in for Raycast's Search Menu Bar Items, ships with its hotkey off (typeToClickHotkeyEnabled = false, Sources/Models/QuickSettings.swift:249). It needs a one-time setup. Its launcher keywords already include 'menus' (Sources/ViewModels/QuickViewModel+LauncherSearch.swift:431), so no keyword change is needed.
- A launcher item's alias is invisible on the row: Sources/Views/LauncherResultRow.swift:22-55 shows title, detail, pin and hotkey only. The alias is stored as typed (Sources/ViewModels/QuickViewModel+LauncherItemConfig.swift:294) but trimmed and folded at read, so this is a display gap, not a matching bug.
- docs/launcher-roadmap-20260822.md is stale: it still marks Process killer (line 70), window cycling (line 73) and 'Assign abbreviation in Cmd-K' (line 106) as not built, but Quit and Force Quit (Sources/Models/ItemAction.swift:234-237), WindowLayout.cycle (Sources/Models/WindowLayout.swift:109-111) and Set Alias in Cmd-K (ItemAction.swift:243) are in Sources.
- Removed as false: the first agent's 'duplicate setting' item. The double-tap right Command switch appears in both the Features card and the Behaviour card on purpose; the comment at Sources/Views/SettingsGeneralTab.swift:36-37 says the Features card is one place to turn each feature on or off and each switch is the same setting its own card uses.

### Root search: where Quick Launch is ahead

- Learned abbreviations: the exact text typed when an item is chosen ranks it first next time, per catalog, with a 14-day decay (Sources/Services/LauncherUsageStore.swift; docs/launcher-roadmap-20260822.md line 13). Raycast lists frecency as the lowest of its five ranking tiers (search-bar.md, 'How Ranking Works').
- Local, content-free interaction journal with review and export (Settings, General, Learning & Review; Sources/Services/InteractionJournalExport.swift). The Raycast docs read here describe nothing like it.
- In-app keys are rebindable from one pane with collision checks against fixed keys and global hotkeys (Sources/Models/ShortcutAction.swift:498-552). Not checked against the Raycast docs in this pass.
- Root search and Settings share one settings index: typing a setting's name in the launcher opens that card (Sources/Models/SettingsDestination.swift).
- Escape and Backspace step back one layer at a time (handleEscapeKey, Sources/ViewModels/QuickViewModel+LayerStack.swift:187; popLayerForEmptyBackspace), and Keep my place restores the layer on reopen. Raycast's equivalent is the Pop to Root Search delay, up to 180 seconds.
- Type to Click labels controls and menu items of the frontmost app and clicks by typed name; this is wider than Raycast's Search Menu Bar Items, which covers the menu bar only.
- Local answers (math, units, dates, city times) are computed on the Mac (Sources/Services/LocalConversionResolver.swift) and Tab always opens Quick AI whatever the fallback list holds (QuickViewModel+FallbackCommands.swift:21).
- Selected text raises matching saved actions in root search (selectionBoost, Sources/ViewModels/QuickViewModel+QuickAISize.swift:387).
- Hide from Quick Launch works on any row kind and is restorable from Settings, Items, Hidden, even when the source app is uninstalled (Sources/Models/LauncherItemConfiguration.swift:35; ItemAction.swift:170-172).
- Global hotkeys use Carbon RegisterEventHotKey (Sources/App/GlobalHotKey.swift), which needs no Accessibility or Input Monitoring grant.
- App row actions go further than plain launch: Quit, Relaunch, Force Quit and Hide Windows with direct keys from the list (Sources/Models/ItemAction.swift:233-239).
- No account, no telemetry, no paid tier; keys stay in the macOS Keychain (project CLAUDE.md, 'Preserve').

### Clipboard, snippets, Quicklinks, emoji: built but half-wired, hidden or undocumented

- Snippet placeholders are undocumented: {cursor}, {clipboard}, {date}, {time}, {argument name= default= options=} and the Quicklink {query} slot work (Sources/Services/SnippetPlaceholders.swift, QuickLinkQuery.swift) but docs/features.md 'Snippets and Quicklinks' (lines 322-331) never mentions them; the only hint is one caption in the edit form (Sources/Views/ItemActionPane.swift:107-113).
- {cursor} is advertised in the edit-form hint but only removes itself: SnippetExpansion.cursorOffset is computed and tested but never read (Sources/Services/SnippetPlaceholders.swift:122-165; Sources/ViewModels/QuickViewModel+Snippets.swift:133 uses .text only).
- Two spellings for the Quicklink input slot: Settings says 'Links with {{input}} ask for text first' (Sources/Views/ClipboardLinksSettingsView.swift:319) while the edit form and code teach {query} (Sources/Views/ItemActionPane.swift:111,228; Sources/Services/QuickLinkQuery.swift:9). A link saved with only {{input}} is rendered but not flagged requiresInput on create (LauncherCatalogService.swift:196,222 test only {query}).
- Wrong code comment: Sources/Services/QuickLinkQuery.swift:3-4 says Raycast spells the slot {query} 'the same way'. The Raycast manual uses {argument name="query"} (raycast-docs/quicklinks.md, Supported Links), so a Raycast link does not work as pasted.
- Likely bug, unverified at runtime: a snippet with an {argument} run by its own global hotkey enters the argument prompt without showing the panel. Sources/App/AppDelegate+Hotkeys.swift:257-261 calls showOverlay only for a Quicklink with requiresInput; snippets go to performLauncherItem, and insertSnippet only calls enterInputMode (Sources/ViewModels/QuickViewModel+Snippets.swift:107-118), which bumps a focus counter and does not present the overlay (Sources/ViewModels/QuickViewModel+InputModes.swift:14-37; QuickViewModel+SubmitPipeline.swift:8-10).
- Stale Settings wording says text only: 'Keep text clipboard history' and 'N saved text items' (Sources/Views/ClipboardLinksSettingsView.swift:41-43,159) although the history stores images, rich text and files.
- Clipboard retention can never be reached: 'Keep copies for' offers up to 1 year (Sources/Models/ClipboardSource.swift:56-65) but the count stepper tops out at 200, defaults to 50 (Sources/Views/ClipboardLinksSettingsView.swift:52-60), and the store clamps to 200 a second time (Sources/Services/ClipboardHistoryStore.swift:220), so the count prunes long before the time limit.
- Useful clipboard actions have no key: Paste as Plain Text, Rename…, Attach to Question, Open, Copy Text from Image, Copy Text from QR Code and Save as File… all carry `shortcut: nil` (Sources/Models/ItemAction.swift:284-307).
- The Snippets, Quicklinks and Emoji & Symbols catalogs have no direct hotkey and no settable alias: a catalog row offers only Browse (Sources/Models/ItemAction.swift:226-227) and no command opens a catalog. Corrected: individual snippets and Quicklinks are listed in Settings > Items with alias and hotkey columns (Sources/Views/ItemsSettingsView.swift:26-34,109-115,303-304), but text and address can be edited only from ⌘K in the launcher; the 'Snippets & Quicklinks' card shows two counts and Reload.
- The clipboard skip-apps list ships empty and wants a hand-typed bundle identifier (Sources/Views/ClipboardLinksSettingsView.swift:134-146; Sources/Models/QuickSettings.swift:198). Concealed markers still protect password managers.
- docs/features.md 'Clipboard History' (docs/features.md:309-320) does not mention the source:, tag:, kind:, pin: filters, rename, OCR search, Copy Text from Image/QR, Save as File, retention, Universal Clipboard or the skip-apps list, all of which exist (Sources/Models/ClipboardSource.swift:189-241; Sources/ViewModels/QuickViewModel+Clipboard.swift).
- Stored Quicklinks that are not http/https are dropped silently on load (Sources/Services/LauncherCatalogService.swift:246-249 compactMap), so the Settings count can be lower than the file's content.
- The legacy Tuna import still reads ~/Library/Preferences/com.brnbw.Tuna.plist and Tuna/config.toml on a first run without a catalog file (Sources/Services/LauncherCatalogService.swift:92-97,122-139); it is the app's only import path and is useless to any other user of the public repo.

### Clipboard, snippets, Quicklinks, emoji: where Quick Launch is ahead

- Clipboard privacy: concealed, transient and auto-generated pasteboard markers are always skipped, and AI answers copied by the app are marked transient so they never enter history (Sources/Services/ClipboardHistoryStore.swift:372-380). (The Universal Clipboard default is the same as Raycast's, so it is not counted as ahead.)
- Clipboard filters Raycast does not document: by the app in front at copy time (source:App, tag:App) and pin:true, typed in the search field (Sources/Models/ClipboardSource.swift:189-241).
- Shorter retention choices (5 minutes, 1 hour) and a hard 200 MB byte budget that never evicts a pin (Sources/Models/ClipboardSource.swift:56-65; ClipboardHistoryStore.swift:214-220).
- Save a clipboard entry as a file, and open a copied file or link straight from history (Sources/Models/ItemAction.swift:286-288,305).
- Clipboard to Quicklink in one key (⌘⇧L) and Copy Clean Link, which strips tracking parameters (Sources/Models/ItemAction.swift:300-303,352-354).
- Any snippet, Quicklink, app, folder or command takes its own global hotkey and alias from ⌘K or from the Settings > Items table, plus Hide from Quick Launch (Sources/Views/ItemsSettingsView.swift; Sources/ViewModels/QuickViewModel+ItemActions.swift:82-95).
- Snippet placeholder engine is safer on real text: an unknown {name} or modifier stays literal, \{ escapes a brace, and date offsets also take weeks and seconds (Sources/Services/SnippetPlaceholders.swift).
- Paste goes to the app that was in front, and the action title names it ('Paste to Word') (Sources/Models/ItemAction.swift:257).
- Save an AI answer as a snippet from the answer's actions (ResultAction.saveSnippet, Sources/Models/ItemAction.swift:509,544).
- Copy or paste text from a dragged screen area with on-device OCR, and OCR search over saved screenshots, alongside clipboard image OCR (commands ocr.area and ocr.areaPaste, Sources/ViewModels/QuickViewModel+LauncherSearch.swift:328-336).
- Everything is local and free: no account and no Pro tier for retention beyond 3 months (Raycast gates 6 months, 1 year and unlimited behind Pro); the snippet catalog is an owner-only JSON file (Sources/Services/LauncherCatalogService.swift:3-7).

### Utilities: where Quick Launch is ahead

- Window management for one window is free and complete, with sixths, Almost Maximize, Make Smaller/Larger and half → two-thirds → third cycling (Sources/Models/WindowLayout.swift:5-31, :113-114, :133-147); Raycast's doc marks window management 'Tier: More with Pro' (window-management.md:12).

- Calendar and tasks are wired to the real work stack (Outlook work calendar, Todoist, PRs, Slack, mail through plate.py and calendar-ops.py) with numbered rows (`3 done`, `2 move to 16:00`), Return-to-confirm writes and Command+Z undo (Sources/ViewModels/QuickViewModel+Worklist.swift, Sources/Services/ChatToolbox+Changes.swift, Sources/Services/CalendarListing.swift). Raycast's calendar writes to the macOS Calendar, and its AI extension can create, edit and delete without this proposal step.
- Event moves are limited to solo events, so the app cannot notify another person; Raycast offers accept/decline, email attendees and delete, which the contract rules out on purpose.
- Type to Click: label and click any control or menu item in the frontmost app by typing (Sources/App/TypeToClickPolicies.swift, Sources/Services/TypeToClickService.swift). Not in Raycast's docs for this area.
- Caffeinate with timed sessions, 'until a time', battery cutoff and Agent Watch (stays awake while Claude Code or Codex works) is built in (Sources/Services/CaffeinateManager.swift, CaffeinateSchedule.swift, AgentSessionWatcher.swift); Raycast's docs here have no keep-awake command.
- House commands: other apps publish commands through a JSON manifest with live status gating and choice pickers (Sources/Services/HouseCommandCatalog.swift, HouseCommandDirectory.swift); installed today are Dictation, Memory (Capture a Thought, Search Memory, Today, Open Tasks), Models and RTI recording. A cleaner contract than script headers for the user's own apps.
- Process safety: every command runs as argv with no shell (Sources/Services/CommandActionRunner.swift:1-5, ProcessRunner.swift); Raycast script commands run whatever the script's interpreter is given.
- System Settings panes are searchable commands (Sources/Services/SystemSettingsPaneCatalog.swift) and Toggle Desktop Icons exists (QuickToggleService.swift:12); Raycast's System Commands list has neither.
- Local answers never reach a model and are labelled 'Local answer' (Sources/ViewModels/QuickViewModel+InteractionJournal.swift:396); no account, no telemetry, no cloud sync, and a content-free interaction journal for reviewing misses (Sources/Services/InteractionJournal.swift).
- Per-app Hide, Quit, Relaunch and Force Quit from the app row with Command+K (Sources/Models/ItemAction.swift:234-239), and learned ranking of root results (Sources/Services/LauncherUsageStore.swift).

### Backup, sync, platform: where Quick Launch is ahead

- No account, no subscription, no server: every feature works signed out. Raycast needs a signed-in Pro account for Cloud Sync and scheduled exports, and pauses scheduled exports when the plan lapses (import-export.md > Scheduled Exports).
- Bring-your-own keys and custom OpenAI-compatible and CLI providers are the default (Sources/Models/InferenceProvider.swift, Sources/Services/APIKeyStore.swift). Raycast documents BYOK and Custom Provider under enterprise/ (enterprise/byok.md, enterprise/custom-provider.md).
- Secrets never leave the Mac: Keychain items are written with iCloud Keychain sync switched off on purpose (Sources/Services/KeychainStore.swift:16-27, 82). Raycast also never syncs credentials, so this is equal; here nothing else syncs either.
- No sync means none of Raycast's documented sync failures: hotkeys or settings reverting on a new device, duplicates after migration, notes overwritten from iOS, lossy window layouts (cloud-sync.md > Troubleshooting).
- Chats are kept until deleted in a content-addressed, owner-only archive with the original attachment bytes and hashes, and each retained source can be opened or exported from the chat (Sources/Views/ChatContextRecordView.swift:380-388, Sources/Views/QuickAIThread.swift:535). Raycast's docs describe no per-source export.
- Single-chat export as plain JSON, unencrypted and readable by any tool (Sources/Views/AIChatWindowView.swift:587-641). The Raycast docs describe chat export only inside the encrypted .rayconfig.
- A content-free interaction journal that exports as JSON Lines or Markdown and can be cleared or turned off (Sources/Views/SettingsGeneralTab.swift:461, 588-589; docs/product-scope.md:56). The Raycast docs describe no user-readable usage log; they offer raw app logs instead.
- Settings blobs from older builds load through a versioned decoder with per-field defaults (Sources/Models/QuickSettings.swift:133, 344-346, configurationVersion 28), so importing an old backup is cheap to make safe.
- One clipboard entry can be saved to a file in its native format from the launcher (Sources/ViewModels/QuickViewModel+Clipboard.swift:315-348).
